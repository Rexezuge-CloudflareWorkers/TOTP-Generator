# AGENTS.md - TOTP-Generator

## Project Structure

A pnpm workspace with two packages and three TypeScript projects outside them:

- **`apps/api/`** — the Cloudflare Worker: a Hono app with chanfana OpenAPI routes, otplib generation, the error envelope, security headers and the rate limit (`@totp-generator/api`).
- **`apps/web/`** — the React SPA: Vite + TailwindCSS v4 + React 19 on `@rexezuge/web` components (`@totp-generator/web`).
- **`functions/[[path]].ts`** — the Cloudflare Pages Function that proxies `/generate-totp`, `/generate-totp-batch`, `/docs` and `/openapi.json` to the worker over the `API_WORKER` service binding.
- **`test/`** — the two suites. `test/api` runs under the node pool and aliases `@totp-generator/api` to `apps/api/src`; `test/web` runs under jsdom against `apps/web/src`.
- **`scripts/prepare-wrangler-config.ts`** — materialises `wrangler.jsonc` from `apps/api/wrangler.template.jsonc`.
- **`scripts/verify-tailwind-kit.ts`** — fails the build when the kit's Tailwind classes are absent from the emitted CSS.

The kit is `@rexezuge/*` 1.9.2, pinned by this repo's own `pnpm-workspace.yaml` overrides.

## Key Commands

```bash
pnpm install                 # also runs `pnpm run typegen` via postinstall

pnpm run checks              # typecheck → lint --fix → format:check → god-files → both suites
pnpm run typecheck           # both packages + the test/, functions/ and scripts/ projects
pnpm run lint                # eslint --fix --quiet .
pnpm run format:check
pnpm run check:god-files
pnpm run test / test:coverage           # API suite
pnpm run test:web / test:web:coverage   # SPA suite

pnpm run build               # SPA → apps/web/dist, then the Tailwind kit check
pnpm run verify:tailwind     # the kit's classes reached the built CSS
pnpm run prepare-config      # template → wrangler.jsonc, patched from the environment
pnpm run dev                 # wrangler dev on :8787
pnpm run deploy              # prepare-config + wrangler deploy
pnpm run deploy:dry-run      # the same bundle, no upload
```

## Important Configuration

- **`wrangler.jsonc` is generated and gitignored.** `apps/api/wrangler.template.jsonc` is the committed source: worker name `totp-generator`, assets served from `apps/web/dist`.
- **Pages uses its own template.** `apps/web/wrangler.template.jsonc` carries `pages_build_output_dir` and the `API_WORKER` service binding; the deploy copies it over `wrangler.jsonc`.
- **CI/CD patch the template rather than duplicate it**: the `WRANGLER_JSONC`, `WRANGLER_PATCH_JSON` and `WRANGLER_VARS_PATCH_JSON` repository variables are read by `prepare-config`.
- **One zod copy.** `pnpm-workspace.yaml` overrides `zod` to the workspace's exact version because chanfana types a route's request body through its own zod, augmented by `zod-to-openapi`; a second copy makes `z.object(…)` unassignable to `OpenAPIRouteSchema` with a "Property 'openapi' is missing" error.
- **`worker-configuration.d.ts`** is generated by `wrangler types` (postinstall) and gitignored; `apps/api/src/types.d.ts` bridges it to the runtime's `Env`.
- **The kit's Tailwind classes need an `@source`.** `@rexezuge/web`'s components are class-based, and their class names live in the package's `dist/*.js` — which Tailwind never scans, because automatic source detection skips `node_modules`. `apps/web/src/globals.css` therefore declares `@source '../node_modules/@rexezuge/web/dist';`. Without it the build succeeds, this repo's own classes still apply, and every kit component renders unstyled: no card background, no border, no radius, no padding. `scripts/verify-tailwind-kit.ts` runs after every build and fails when the kit's utilities are missing from the emitted CSS, because the failure mode is silent. The kit's `README` documents the CSS-variable contract but not this `@source` requirement.

## Architecture Notes

- **Worker entry**: `apps/api/src/TotpWorker.ts` (an `AbstractEntrypointWorker`): `cors()` → `securityHeaders(isSensitivePath)` → `rateLimit(…)` → chanfana routes → `app.notFound` / `app.onError`. `apps/api/src/index.ts` exports it.
- **Errors**: routes throw `BadRequestError`; chanfana rethrows (`raiseOnError`), so `app.onError` is the single boundary. It maps through `BaseRoute.toErrorResponse` to the `{Exception:{Type,Message}}` envelope and logs only 5xx (`reportUnhandled`), because a 5xx message is masked for the client.
- **Rate limit**: 60 requests per minute per client address, per isolate. The `RATE_LIMIT_*` constants and `isSensitivePath` live in `TotpWorker.ts` and are asserted by the worker tests.
- **SPA**: `lib/otp.ts` holds the pure helpers, `lib/api.ts` the fetch client, `hooks/useTotpBatch.ts` the state machine (500 ms debounce, 1 s countdown tick, rollover refetch keyed on the step, abort of superseded requests, error notice), and `components/` the three cards. The auto-refresh preference persists in `localStorage` under `totp-generator:auto-refresh`.
- **Pages routing**: `apps/web/public/_routes.json` decides which paths hit the Function; the rest are served as static assets.

## CI/CD

- **`continuous-integration.yml`** — on pull requests, pushes to `main`, manual dispatch, and the fork-sync dispatch. Jobs: `checks`, `unit-tests`, `web-tests`, `build` (SPA bundle + `wrangler deploy --dry-run`), `dependabot-auto-merge` (the only writer, waits for every gate) and `dispatch-upstream-sync-deployment`.
- **`continuous-deployment.yml`** — after CI succeeds on `main`, on the `Upstream Sync Deployment` dispatch, or manually. Jobs: `deploy-worker` and `deploy-pages`. Secrets: `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`. Optional variable: `CLOUDFLARE_PAGES_PROJECT_NAME` (default `totp-generator-app`).
- **`upstream-sync.yml`** — forks only, weekly: pulls from upstream and dispatches `Upstream Sync Integration` at CI so the deploy is authorised by a CI run, not by the sync.
- **`backup-main.yml`** — mirrors `main` to Azure DevOps and/or GitLab when the `BACKUP_REPO_*` secrets are set; skips entirely otherwise.
- **Node 24**, pnpm from the root `packageManager` field.

## TypeScript Configs

- Root `tsconfig.json` holds the shared options; `apps/api/tsconfig.json` and `apps/web/tsconfig.json` are the two packages.
- `test/tsconfig.json` aliases the two apps by package name and includes the generated worker types plus the API's `types.d.ts`.
- `functions/tsconfig.json` covers the Pages entrypoint; `scripts/tsconfig.json` covers the build script and needs `allowImportingTsExtensions` because it imports `@rexezuge/tooling`'s shipped `src/` directly.
